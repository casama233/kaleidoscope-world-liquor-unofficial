# Current Java critical feedback and LivingDamage scope

Reference: author World Liquor NeoForge1.21.1 **1.1.11 / CF9066406**, `EventHandlers.onLivingDamagePre` and `DoubleDamageEffect`; official Minecraft1.21.1 `Player.crit`, `TrackingEmitter`, `CritParticle`, `Particle`, `SingleQuadParticle` and server `Level.addParticle` bytecode. Ground crit and player-credited double damage each invoke a tracking emitter; both procs on one damage retain two calls.

The emitter makes16 float random attempts in each of three ticks. Unit-sphere rejection means the visible count varies. Accepted positions use target width-scaled X/Z offsets and height-scaled Y fraction; each frame follows the current target in its original dimension. Removed targets retain the last snapshot for the remaining frames, as the Java client emitter retains its Entity reference. No UI, dynamic properties, simulated players or foreign player definition is added.

Nonplayer double damage calls the base server Level.addParticle method, which is a no-op in this branch; ServerLevel does not override it. Adding a five-particle broadcast here would change the original. The numeric constructor reproduces superclass random noise/normalization, source floats for base size/color, lifetime, input velocity and damping. Private Java Random48 streams keep cosmetic sampling out of damage's Math.random draws; independent native/client seeds are not claimed identical.

The RP uses the unmodified Minecraft1.21.1 critical_hit sprite, camera-aligned billboard, world lighting, no terrain collision, source20Hz gravity0.02/friction0.7f, tickwise green0.96f/blue0.9f and interpolation. These data rules do not certify client rasterization, timing, light map, density/distance handling, blend/material or all floating precision; those remain paired-client acceptance for dot. The source texture remains under Mojang's original terms.

The script queues feedback only for an accepted native hurt, discards later cancellation or native cooldown rejection and clears the transient pending row. The native event has nonenumerable fields; the probe forwards the actual native properties rather than spreading the wrapper. The earlier failed probes are retained locally: one exposed that harness forwarding mistake; another counted the final frame of an earlier successful critical in the rejection window. The final measurement separates those events and passes.

A related logic repair limits the damage adapter to source LivingEntity equivalents: player, armor stand or health-bearing mob family. Native health-bearing boats no longer get extra damage, feedback or kill credit. Arbitrary addons must advertise their entity family; unclassified Java/Bedrock class/tag equivalence remains an explicit adaptation gap.

Evidence:18 Java constructor/RNG numeric rows, production logic regressions, actual native mobs with accepted/canceled/rejected feedback requests, and production previous-credit native regression. The deterministic native accepted case emits48 because all test sphere samples are centered; it is not the ordinary random visible count. Native requests and RP loading do not prove rendered particles. Full-family source/static/BDS/fresh-stopped-world/remote gates are still required for release.
