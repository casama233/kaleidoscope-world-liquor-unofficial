# Current Java movement repairs and boundaries

Reference: author World Liquor NeoForge1.21.1 **1.1.11**, CurseForge9066406. `BoatMixin`, `LivingEntityMixin`, `ClientPlayerEntityMixinHooks`, plus official Minecraft1.21.1 `LivingEntity.jumpFromGround/travel` and `Mth`. Forge1.1.12/26.1.2 branches remain distinct adaptation work.

The previous boating implementation invented water/ice/land coefficients, per-surface caps and amplifier slope. It also allowed passengers to apply another multiplier. The new numeric rule preserves source float arithmetic, cap1.2, brake0.85f and the1e-4 squared-speed threshold. Only the rideable controlling seat applies it. Actual native vanilla-boat mount/eject measurements confirm rider order; arbitrary third-party boats have not been certified.

Multi-jump now reads held input at each tick, refills on ground/climb, consumes a jump only on a fresh eligible press while falling, and uses the reverse falling sign when applicable. Pressing during ascent and keeping the key held no longer turns into an extra jump later. Normal/reverse sprint factors preserve their respective vanilla double0.2/source float0.2f, the Mth sine lookup, jump boost and known honey jump factor. It does not rewrite player health, inventory, foreign effects or saved dynamic properties.

Native impulse arrives after gravity/drag. Plain reverse0.16 yields0.0816 after a zero-velocity frame; the source post-travel result is0.0784. Production compensates this phase instead. Levitation reverse targets-0.05*(amp+1); ordinary head boost is skipped. Slow fall uses source0.09 boost, accounting for native's strict-negative gravity condition versus Java's nonpositive condition. Real liquid contact uses API2.7 BlockVolume/getBlocks/AABB because isInLava is absent.

`tests/fixtures/JavaMotionOracle.java` evaluates92 Java numeric inputs. `tests/multi-jump.test.mjs` executes production callbacks against deterministic API fixtures; those are not simulated Minecraft players. `tools/run_native_motion_probe.py` runs real native mobs in a new isolated empty-allowlist QA world and logs six motion/fluid scenarios, each with five samples. The report describes tolerance and scope; the zero/slow/levitation/default-air/deep-lava numeric results do not prove every player physics combination.

**Still open:** inverted ground requires Java's translated AABB ceiling collision, while native isOnGround remains readonly; the ground-button branch retains the existing native contact adaptation. It is not counted as inverted ground parity. Java moves before tail damping, while this native phase moves with its sampled updated velocity. Complete travel positions/xz drag/air-input, client tick ownership, custom jump attributes/blocks, source shallow-lava height<=0.4 and fluid entry/exit phase, passengers with unusual seat layouts, step/collision details remain unverified or unimplemented. The AABB fluid contact correctly suppresses the reverse head boost but cannot by itself prove native travel picked the same fluid branch.

The camera source adds **540.35394f** to original roll, adjusts eye height, reverses input and adjusts picking. API2.7 exposes Camera.playAnimation with Vector3 rotation frames and a native LinearSpline; this is an investigation route, not a working camera adapter or proof that roll/other-addon composition works. No camera lock was installed. CaptainGift, FrostWalker, outlines, Highball flight and remaining audio/particles remain in the full goal.

Full-family static/native/fresh-saved-world and remote PR delivery are separate release gates. All human scene results remain pending, client=false/production_ready=false until the owner provides paired observations.
