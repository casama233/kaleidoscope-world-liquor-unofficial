# World Liquor 0.1.96 — original ordinary freezer input settlement

Source: current maintained NeoForge1.21.1 author1.1.11, CurseForge9066406. `FreezerBlockEntity.insertItem` copies one item into its first empty input slot, then shrinks the held stack and assigns it back **without a Creative exemption**. The existing compact four-entry layout is contiguous, so appending represents that first empty slot. `extractItem` scans backward, removes one from the last occupied slot, then calls `player.addItem` and ignores its boolean return. The new helper follows these orders, uses the shared Java inventory insertion priority, and never invents a drop or full-inventory message for this unchecked input return. A last inserted item empties its original hand; stacked input retains the remainder. Existing milk, output and fluid branches remain separately defined.

`FreezerBlock.useItemOn` plays ITEM_FRAME_ADD_ITEM only after successful insertion. `useWithoutItem` plays ITEM_FRAME_REMOVE_ITEM after the attempt, including an empty input inventory. Both are BLOCKS-category, centered, volume0.8f and pitch1.1f; the selected original Minecraft1.21.1 OGG samples/event entries come from the official publisher index. Callback audio and visual failures do not reverse settled contents. No success text or polling announcement is added.

This release does **not** complete input ItemStack persistence. Existing unrepresentable names/lore/dynamic properties/enchantments are still rejected rather than discarded. The recognized quality-tooltip exception and string-ID storage remain incomplete metadata adapters. A native container must retain complete stacks across insertion, crafting, removal, break, unload and restart before claiming that gap fixed. The existing host native-storage contract covers cabinets, not freezers; it is not silently repurposed or made dependent on luosen-only addons.

Owned SDK writes are journaled and recovered on SDK errors; a changed captured origin is rejected without replacing the foreign stack. These adapters do not reproduce arbitrary Java ItemStack reference aliases, callback hooks or packets. The artificial full-inventory helper fixture verifies the source's ignored return; ordinary empty-main-hand extraction normally already has one free slot. It is not a reproduced native full-inventory Player case. SDK fixtures are neither simulated players nor client acceptance. The existing immutable clock evidence remains relevant only to unchanged clock behavior.
