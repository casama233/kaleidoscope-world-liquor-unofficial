# World Liquor0.1.80 treasure-guide block drops

Current author **NeoForge1.21.1 World Liquor1.1.11 / CF9066406**, `EventHandlers.onBlockBreak` lines330–347, checks the Java crop tag/CropBlock class or `Tags.Blocks.ORES` and evaluates `min(0.15 + amplifier*0.05,1)`. It independently calls `Block.getDrops` using the original state and main hand, then adds fresh stacks at block center. It does not copy whichever new item entities happen to appear nearby.

The previous port used name suffixes, erroneously included cocoa/nether wart, omitted ancient debris, used20% for ores and cloned new nearby entities after a delay. Concurrent activity could duplicate another player's drops, and extra crop/ore drops could incorrectly equal the already-rolled normal drop. The canonical0.1.80 adapter now selects the source default crop/ore membership and explicit native equivalents, uses15% for both, evaluates the original broken permutation with `itemStackBeforeBreak`, clones all returned stack components and emits at block center. It does not scan nearby items, defer the block roll or substitute a new tool. Source default membership is captured in `data/java-treasure-block-source.json` from the pinned official MC1.21.1 archive and NeoForge1.21.1 commit a2d6402a3c1eec093aef7e7d10ac5145906c199e.

Native stable2.7.0 exposes [permutation loot generation](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/loottablemanager?view=minecraft-bedrock-stable). Eight actual native cases verify15% versus the old20% interval, immature wheat, excluded nether wart, ancient debris, two independent tagged custom blocks and the original silk-touch tool. Seven nearby emeralds stay seven; the six expected extra native stacks preserve item IDs/amounts and the center position. Five program regressions also exercise the actual registered callback, effect/amp forwarding and source state/tool selection. None is a simulated player or actual player-break/client acceptance.

## Other addons and standalone operation

No luosen package, configuration or global resource pack is needed. The paired Tavern dependency remains required. Native producers may use `minecraft:tags` under block format1.26.20+ to declare `c:ores` (or one of its ten source referenced subtags), legacy source `forge:ores`, or `kaleidoscope_world_liquor:crop_block` for a Java CropBlock/source crop equivalent. A nonstandard registry name does not require `_ore` or `_crop`. The [1.26.20 tag format](https://learn.microsoft.com/en-us/minecraft/creator/documents/update1.26.20?view=minecraft-bedrock-stable) replaces unsupported old `tag:...` components for this format. The failed old-format QA is retained; no such component is installed in runtime.

Only declared source tag equivalence is accepted. Native class identity cannot be inferred from a block name; arbitrary Java tag replacement/removal, custom CropBlock subclasses without a native declaration and arbitrary loot-modifier code remain integration requirements.

## Remaining source gaps

Native permutation generation rejects some insufficient/empty tools whereas Java's direct `Block.getDrops` can bypass normal harvest eligibility. It lacks the source player/luck, position-specific block entity and global loot-modifier context. The native after-break stage differs from Java's cancellable pre-break hook and shared RNG ordering. These remain unfinished; missing native results do not fall back to copying foreign items. Default native loot contents/distributions versus their Java tables and actual player/creative/client results still need comparison. Native vanilla block state aliases retain exact source eligibility, not a claim that every loot table is identical.

Mob treasure-guide still uses its previous nearby-item heuristic; **do not claim full mob-drop parity**. Head resolution/deduplication, persistent beheading marker, recursive IncomingDamage replacement/fallback and source boss-tag extensions remain unfinished. The current author boss tag contains only dragon/wither/warden; the older asset-base boss file contains optional IDs and is not authority for current membership.

Actual native capability observations show that mutating `damageSource` fields does not change resulting native source; recursive `applyDamage` in restricted before-hurt throws; `kill()` creates cancellable selfDestruct damage; health0 death uses override without attacker, and can spawn loot before the death callback. Normal API damage returns before after-hurt/death/item-spawn callbacks. This evidence constrains a faithful future beheading/mob-drop adapter; it does not authorize inventing an equivalent kill or claiming full source event parity. See `NATIVE-TREASURE-BLOCK-20261007.json` and `NATIVE-BEHEADING-CAPABILITIES-20261007.json`.
